# avoid.md：什么不要做

**回答**：禁止的视觉风格、UI / 组件 / 布局 / 内容 / 交互反模式，以及 AI 常见问题。
**不回答**：正向规范（分散在 prd / visual / design / ui-patterns / page-specs）。

**写法要求**：每条都要写「错在哪 → 改成什么」。只列禁止项不给替代方案，等于没写。

## 每节写什么（附典型条目）

### 1 视觉风格

- 用模板化的默认美学（默认蓝紫渐变、发光边框、无差别圆角卡片）→ 按 visual.md 的方向与 design.md 的令牌做决策。
- 用高饱和大片色块制造「设计感」→ 品牌色只作强调，正文区域保持中性。
- 为了好看牺牲可读性（浅灰文字压浅底）→ 对比度按 design.md 底线执行。

### 2 UI 反模式

- 层级混乱：所有文字差不多大、所有按钮都是主按钮 → 每屏只有一个主行动。
- 无反馈：点击后没有任何变化 → 提交中禁用 + 进行中指示；成功/失败给出提示。
- 焦点丢失 / 不可键盘操作 → 所有交互元素可聚焦、可见焦点环。
- 用颜色单独表达状态（红绿）→ 颜色 + 文字/图标双重表达。

### 3 组件反模式

- 手写基础标签绕过组件库（自造按钮、自造输入框）→ 用组件库组件与官方组合方式。
- 把按钮塞进输入框时用相对定位硬拼 → 用组件库提供的输入框组合（如 addon / group）方案。
- 复制粘贴同一段 UI 到多处 → 抽成 Block。
- 直接修改组件库生成的源码 → 在自己的组合组件里适配。
- 包装组件库组件后不重测焦点环、报错态、禁用态。

### 4 布局反模式

- 魔法数字（随手的 `margin-top: 37px`）→ 用间距尺度里的档位。
- 写死宽高导致窄屏横向滚动 → 响应式按 design.md 的断点验证到最窄档。
- 忽略断点，只测桌面 → 每个断点都实际跑一遍。
- 长文本不设溢出策略 → 明确换行、截断或撑开。

### 5 内容反模式

- 硬编码业务文案（中英文写死在组件里）→ 一律走文案字典，多语言同时补齐。
- 术语前后不一致（同一概念两种叫法）→ 在 prd.md 里定对照表。
- 占位内容（Lorem、TBD、待补充）留在交付物里 → 交付前清零。
- 只写「10 条数据」这类具体数字进用户可见文案 → 文案要么不提数量，要么由数据驱动。
- 用假数据冒充真实数据且不标注 → 明确标注为演示数据。

### 6 交互反模式

- 动画卡顿或一卡一卡（逐张跳、到头跳回起点）→ 连续匀速位移，且提供暂停（悬停/聚焦）与 reduced-motion 降级。
- 自动播放且无法停止，或抢占焦点 → 提供暂停条件，不抢焦点。
- 破坏浏览器行为（禁用回退、劫持滚动、无法用新标签打开）→ 保持原生行为。
- 弹窗关闭后丢失用户意图 → 关闭/登录成功后回到原意图。
- 头部导航堆到 8 项以上 → 收敛到 ui-patterns.md §8 的头部项数上限，其余归入下拉或页脚。
- 用没有文字的图标当导航 → 图标必须配文字标签。
- 桌面端把主要导航藏进汉堡菜单 → 桌面用常驻头部，汉堡只用于移动端折叠。
- 页脚倒成几十条链接的清单 → 按 ui-patterns.md §8 的主题列分组。
- 面包屑与 URL 层级对不上（面包屑写「产品 > 小组件」而地址是 `/shop/widget-pro`）→ 以 URL 层级为准改正。
- 导航在不同页面长得不一样 → 全站同一套（应用内页与营销页除外）。
- 导航是纯 JS 的假链接（打不开新标签、爬不到）→ 用真实链接或路由组件。

### 7 AI 常见问题

- **自造需求**：加了没人要求的功能、配置项、「灵活性」→ 只做需求内的，其余先问。
- **过度抽象**：为一次性代码建抽象层 → 出现第三处重复再抽象。
- **顺手重构**：改了无关代码、格式、注释 → 每行改动都要能追溯到本次需求。
- **无证据宣称完成**：说「已优化」「很流畅」但没测 → 给出可复核的证据（命令输出、测量数值、截图）。
- **文档与代码不一致**：改了行为没回写文档 → 按 SKILL.md 的回写表同步，再交付。
- **只跑通正常路径**：没试失败、空数据、未登录、最窄屏幕。
- **凭记忆写框架 API**：不核对当前版本文档就下手 → 先读项目内该框架的文档/现有用法再写。
- **一次改多个模块**：出了问题无法归因 → 一次一个模块，做完先让用户验收。

### 8 拒绝的默认套路

这些是**类别默认值**，不是绝对禁令：brief 明确要求时可以用；轴线空着时还去拿它，说明没在做决策。
**发现后要重写该元素，而不是把它调弱。**

页面骨架：

- 用同尺寸的「图标 + 标题 + 正文」卡片堆成页面结构 → 按内容关系选容器，卡片只在真正需要独立边界时用；嵌套卡片一律拆掉。
- 标题上方加 kicker / eyebrow 小标签 → 删掉标签，让标题自己扛重量（这条没有 brief 能换回来）。
- hero 用「大数字 + 小标签 + 支撑数据 + 强调色」模板 → 用主题世界里最有代表性的东西开屏（一张图、一个可交互演示、一句真话）。
- 给区块加 01 / 02 / 03 编号 → 只有当序列本身就是读者需要的信息时才留，否则删。
- 既不需要打断、也不需要保护焦点的任务用弹窗 → 就地展开或跳转页面。

表面习惯：

- 渐变文字 → 强调靠字重或字号。
- glass / blur 当装饰 → 只在它表达具体效果时用，否则纯色或纯描边。
- 卡片、列表项、callout、alert 上 >1px 的彩色左边框 / 右边框 → 用背景色块或图标表达语义，边框回到 1px 中性色。
- 硬偏移阴影（`box-shadow: 4px 4px 0`）→ 除非整体世界确实是新粗野主义，否则回到「有偏移 + 柔和模糊」的阴影。
- 迷你折线、进度环、带柔影的圆角矩形冒充内容 → 换成真实数据或真图，没有就留白。
- 把 monospace 当「技术感」装饰 → 只用于代码、数据、度量。
- 用系统 display 字体（Impact、Arial Black、平台默认无衬线）当标题声部 → 选自托管且与既定字风格相符的字体，装不到就换方案，不退回系统字体。
- 用 emoji / Unicode 字符冒充图标 → 用真实图标库或自制 SVG，笔画与字重统一。
- 用几何形状假装照片主体轮廓 → 从原图导出 alpha 遮罩，或干脆不做（廉价版比不做更差）。
- 按品类直接选浅色或深色 → 按使用场景选：谁、在哪、什么环境光。

模板化痕迹（当前 AI 扎堆）：

- 用近黑冒充纯黑（`#0B0B0B` / `#111`）→ 要么明确用黑，要么明确用中性深灰，说清为什么，别让「差一点的黑」成为无意识默认。
- 元信息用中点连接（`A · B · C`）→ 用分隔线或独立标签，别套这个模板。
- 标签写成 `WORD — fragment`（中间一个空格破折号）→ 用正常标点与句子式大小写。
- 按钮 / 链接文案尾缀 `→` → 箭头只在表达方向时用，否则删掉。
- 小标签全部大写（ALL-CAPS）→ 用句子式大小写，靠字重区分层级。
- 默认套「奶油底 + 衬线大标题 + 陶土色强调」（如 `#F4F1EA` + `#D97757`）→ 按 visual.md 定的方向来，别用这套已被用滥的组合。

数字约定：

- 字距压到 -0.05em 以下 → 停在 -0.04em，-0.02 到 -0.03em 通常更好看。
- 边框和阴影同时上（1px 边框压在大范围柔影上）→ elevation 只声明一次（边框或阴影）；卡片圆角保持 12–16px，胶囊只给小控件。
- 用草图风 SVG / `loose-sketch` / `doodle` / `feTurbulence` 颗粒充当插图 → 换成真插图或清晰的矢量几何（形状、图表、动态线条、着色器仍可用）。
- 用 `repeating-linear-gradient` 条纹 / 双向网格当背景 → 下面必须有真实的画布、地图、蓝图或测量工具撑着，否则用纯色表面。
- 声明与配置凭印象写、演示数值不标注 → 以给定事实为准，演示性数值如实标注。
